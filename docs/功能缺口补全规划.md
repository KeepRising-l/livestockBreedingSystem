## 二、缺口 1：药品疫苗成本核算（P0）

> ✅ **已完成（v1.30，2026-08-18）**：inventory model/schema/service 增加 unit_price（库存均价 + 领用单价快照）、进货审核通过按移动加权平均价更新、出栏成本精确匹配 + 未关联领用兜底均摊、main.py 轻量迁移（加列 + 存量回填）、前端库存均价列/表单单价输入/销售明细药品成本列；后端 SQLite 冒烟测试 4 项断言全过，前端改动文件类型检查零错误。

### 2.1 现状

- `app/modules/finance/service.py` `_calc_animal_cost()`（约 L137-138）：
  ```python
  # 药品疫苗成本：当前物资表无单价，置 0（需物资单价支持后再精确分摊）
  medicine_cost = 0
  ```
  `consumable_cost = 0` 同理。出栏明细 `medicine_cost` 恒为 0，**利润被系统性虚高**。
- `MaterialStock`（`app/modules/inventory/model.py`）**没有单价字段**（只有 quantity/unit/warning_threshold/expiry_date 等）。
- `MaterialPurchase` 有 `cost_price`、`total_cost`，但审核通过（`audit_purchase`）时只更新库存数量，未把单价落到库存。
- `MaterialConsume` 有 `stock_id`、`quantity`、`related_module`（饲喂/防疫/诊疗）、`related_id`，可通过 `related_id` 关联到防疫/诊疗记录，再关联到耳标。
- 进度文档 4.2 自认："药品成本待物资单价支持"——一直未补。

### 2.2 方案

**后端（数据库）**：
1. `material_stock` 增加列 `unit_price NUMERIC(10,2)`（当前库存均价）；
2. `material_consume` 增加列 `unit_price NUMERIC(10,2)`（领用时快照单价，防止后续进货改价影响历史成本）；
3. 存量回填：已有库存按「最近一条审核通过的进货记录 cost_price」回填 unit_price；已有领用按关联 stock 的 unit_price 回填，无则为 0。
4. 因项目用 `Base.metadata.create_all` 自动建表（不 ALTER 已有表），沿用 v1.22 的做法：`app/main.py` lifespan 启动时执行 `ensure_column()` 轻量迁移（查 information_schema → 缺列则 ALTER TABLE），并在 DBD 文档同步补列。

**后端（业务）**：
1. `inventory/service.py`：
   - `add_stock`：入参增加可选 `unit_price`；
   - `audit_purchase` 审核通过时：计算**移动加权平均价** `(旧库存量×旧均价 + 本次进货量×cost_price) / 新库存量` 写入 `stock.unit_price`；新建库存时直接取 `cost_price`；
   - `add_consume` / `audit_consume`：领用记录写入/刷新 `unit_price = stock.unit_price` 快照。
2. `finance/service.py` `_calc_animal_cost()` 补药品疫苗成本：
   - 取该耳标**审核通过**的防疫记录（`vaccine_record`）与诊疗记录（`medical_record`）ID 集合；
   - 取 `material_consume` 中 `related_module IN ('防疫','诊疗')` 且 `related_id IN (上述ID集合)` 且审核通过的记录，`Σ quantity × unit_price`；
   - 兜底：`related_id` 为空（未精确关联）的药品领用，按「该养殖场出栏当月在栏头数均摊」或暂不计入（文档口径：先精确匹配，兜底均摊，二选一，推荐先做精确匹配 + 均摊）。
   - 更新 `total_cost = feed + medicine + labor + consumable`，出栏明细 `medicine_cost` 真实落库。
3. 销售订单详情/利润核算接口无需改动（读字段即可）。

**前端**：
1. `StockListView.vue`：库存表格增加「当前均价」列；新增/编辑库存表单加单价输入；
2. `PurchaseListView.vue`：已有 cost_price 输入，无需改；
3. `SaleListView.vue` 订单详情弹窗已展示 medicine_cost 字段，自动生效；利润核算页自动生效。

### 2.3 验收标准

- [x] 进货审核通过后，库存均价 = 加权平均价正确；
- [x] 领用记录带出单价快照；
- [x] 出栏后订单明细 `medicine_cost > 0`（有药品领用且关联防疫/诊疗时）；
- [x] 利润核算 = 销售额 - (饲料+药品+人工+耗材)，无药品数据时行为与现有一致（为 0 不报错）。

> 实现口径补充：兜底均摊按「物资类型为疫苗/兽药 且 related_id 为空、审核通过的领用总额」÷「出栏当天在栏（在栏/待出栏/隔离/种用）+ 本次出栏数」按只均摊，饲料领用不计入。

## 三、缺口 2：防疫诊疗统计补指标（P1）

> ✅ **已完成（v1.30，2026-08-18）**：`health_stats()` 新增 `month_immunized_animals / immunization_coverage / month_medical_approved / death_count / morbidity_rate / mortality_rate` 六个字段；前端 KPI 扩为 8 卡并加统计口径说明；后端 3 组断言（正常/空数据/除零）全过，前端类型检查零错误。

### 3.1 现状

- `app/modules/statistics/service.py` `health_stats()` 仅返回：`month_vaccine / month_medical / vaccine_dist / disease_dist / treatment_dist / health_trend`。
- 前端 `HealthStatsView.vue` KPI 仅：本月防疫记录 / 本月诊疗记录 / 已康复 / 治疗中。
- **无"应免疫"概念（无免疫计划表）**，无免疫完成率、发病率、死亡率。

### 3.2 方案

**第一步（本期，纯增量统计口径，不建表）**：
1. `health_stats()` 新增返回字段：
   - `month_immunized_animals`：本月已免疫牛只数 = 本月防疫记录去重耳标数（审核通过）；
   - `immunization_coverage`：免疫覆盖率 % = 已免疫耳标数 / 本月平均存栏数（期初+期末/2，或本月最后一日存栏）；
   - `morbidity_rate`：发病率 % = 本月新增诊疗头次 / 本月平均存栏；
   - `death_count`：本月死亡数量 = 本月 `animal_archive.status='死亡'` 的档案数（按出栏/状态变更月份统计，口径见下）；
   - `mortality_rate`：死亡率 % = 本月死亡数量 / 本月平均存栏。
   - 死亡口径说明：档案无死亡日期字段，推荐取 `out_date`（档案置死亡时写 out_date）或诊疗记录 `treatment_status='死亡'` 的记录数，二选一并在文档/页面注明口径（推荐：诊疗记录死亡数，数据最可靠）。
2. 前端 `HealthStatsView.vue`：KPI 增加「已免疫牛只/免疫覆盖率/发病率/死亡率/死亡数量」卡片。

**第二步（可选，后续迭代）**：
- 引入免疫计划表 `vaccine_plan`（farm_id、species、疫苗类型、计划月份、计划数量），统计"本月应免疫 = 计划数、完成率 = 实际免疫/计划"，更贴合 docx 原意；本期不阻塞。

### 3.3 验收标准

- [x] 统计页出现免疫覆盖率/发病率/死亡率 KPI，数值与手工核对一致；
- [x] 无诊疗/死亡数据时返回 0 不报错；
- [x] 口径说明写入页面（KPI 上方 el-alert 提示）。

> 实现口径：分母=当前存栏（在栏/种用/隔离/待出栏）；已免疫=本月审核通过防疫记录去重耳标；发病=本月审核通过诊疗记录数；死亡=本月审核通过诊疗记录中治疗状态=死亡的去重耳标（档案无死亡日期字段，不采用档案口径）。

## 四、缺口 3：存栏繁育统计补比率指标（P1）

> ✅ **已完成（v1.30，2026-08-18）**：`breeding_stats()` 新增 `pregnancy_rate / reproduction_rate / avg_survival_rate / pending_alert_count`；前端 KPI 扩为 8 卡（含 % 后缀）+ 口径说明；后端断言（正常/空数据/除零）全过，前端类型检查零错误。

### 4.1 现状

- `breeding_stats()` 返回：`current_stock / species_dist / gender_dist / stage_dist / pen_dist / month_mating / month_birth / pregnant_count / alert_dist / birth_trend`。
- 前端 `BreedingStatsView.vue` KPI：当前存栏 / 本月配种 / 本月产犊 / 妊娠母畜。
- 无"受孕率、生产率"。

### 4.2 方案

1. `breeding_stats()` 新增：
   - `pregnancy_rate`：受孕率 % = `MatingRecord.status='成功怀孕'` 数量 / （`成功怀孕` + `配种失败`）数量 × 100（有孕检结果才计入，避免把"待孕检"算进去）；
   - `reproduction_rate`：生产率 % = 本月产犊数（`month_birth`）/ 本月配种数（`month_mating`）× 100（无配种时返回 0）；
   - `avg_survival_rate`：平均成活率 % = 全部产犊记录 `survival_rate` 的均值。
2. 前端 `BreedingStatsView.vue`：KPI 增加「受孕率 / 生产率 / 平均成活率」卡片（带 % 后缀）。

### 4.3 验收标准

- [x] 构造配种数据（阳性/阴性）后受孕率正确；
- [x] 有产犊记录时生产率、平均成活率正确；
- [x] 空数据不报错。

> 实现口径：受孕率=**累计**已孕检定论配种（成功怀孕/配种失败）中成功怀孕占比，待孕检不计入；生产率=本月产犊数÷本月配种数；平均成活率=全部产犊记录成活率均值；另补充待处理预警数 KPI。

## 五、缺口 4：公畜档案补全（P1）

> ✅ **已完成（v1.30，2026-08-18）**：新建 `breeding_male` 公畜健康档案表（health_status/use_start_date/semen_quality/remark）；`GET /breeding/males` 返回健康状态/使用年限/配种次数/成功次数/最近配种；新增 `PUT /breeding/males/{ear_tag}/health`；前端公畜列表加列 + 「健康档案」编辑弹窗；后端 5 组断言全过，前端类型检查零错误。

### 5.1 现状

- `/breeding/males`（`app/modules/breeding/api.py`）直接返回 `AnimalOut` 基础字段（耳标/品种/圈舍/生长阶段/状态/出生日期）。
- 前端 `BreedingMaleView.vue` 仅展示基础字段 + 「复制耳标」。
- 无健康状态、使用年限、配种记录；`breeding_male` 表在 v1.25 文档对齐时作为幽灵表被删除，现需重新设计引入（**同步更新 DBD/API 文档**）。

### 5.2 方案

**后端（数据库）**：新建 `breeding_male` 公畜健康档案表：
```
farm_id, ear_tag(唯一), health_status(健康/亚健康/淘汰), use_start_date(启用日期),
semen_quality(精液质量备注, 可选), remark
```
轻量迁移建表（create_all 新表自动建，无需 ALTER；存量公畜回填 health_status='健康'、use_start_date=birth_date 或入栏日期）。

**后端（接口）**：
1. `GET /breeding/males` 返回结构扩展（在 AnimalOut 基础上附加）：
   - `health_status`（扩展表，无则默认"健康"）；
   - `service_years`：使用年限 = 当前日期 - use_start_date（年，保留 1 位小数）；
   - `mating_count`：配种次数 = `MatingRecord.male_tag = ear_tag` 计数；
   - `success_count`：成功配种次数（status='成功怀孕'）；
   - `last_mating_date`：最近一次配种日期。
2. 新增 `PUT /breeding/males/{ear_tag}/health`（body: health_status/use_start_date/remark），走 breeding 权限。

**前端**：`BreedingMaleView.vue`：
- 表格增加「健康状态 / 使用年限 / 配种次数 / 最近配种」列；
- 行操作增加「编辑健康档案」弹窗（状态/启用日期/备注）。

### 5.3 验收标准

- [x] 公畜列表显示健康状态、使用年限、配种次数，数据正确；
- [x] 编辑健康档案后刷新生效；
- [x] DBD/API 文档同步新增 breeding_male 表（待文档对齐时补）。

> 实现说明：`breeding_male` 表由 create_all 自动建（新表无需 ALTER）；无档案记录时默认"健康"、使用年限起点回退出生日期；配种统计（总次数/成功次数/最近配种）由 MatingRecord 动态聚合。

## 六、缺口 5：圈舍详情「移除」操作（P2）

### 6.1 现状

- `PenDetailView.vue` 圈舍内畜禽行操作只有「详情」跳转。
- 后端 `update_animal` 已支持 `pen_id` 变更（校验容量 → 存栏联动 → 自动重生耳标），但**不支持把畜禽移出到"无圈舍"**（schema 需确认 pen_id 是否允许空/置空逻辑）。

### 6.2 方案

1. **后端**：
   - 若 `AnimalUpdateIn.pen_id` 目前不允许置空：新增/放开"移出圈舍"能力（pen_id 置 NULL），逻辑：旧圈舍存栏 -1，耳标释放（ear_tag 置空或保留待重新入舍，推荐置空——与"无圈舍无耳标"规则一致，重新入舍时自动重生）；需同步处理 `generate_ear_tag` 空号复用不受影响。
   - 提供 `POST /animal/{id}/transfer`（目标圈舍）与 `POST /animal/{id}/remove-from-pen`（移出圈舍）两个显式接口（比前端直接拼 update 更安全），校验归属与容量。
2. **前端**：`PenDetailView.vue` 行操作增加：
   - 「转入其他圈舍」：弹窗选择目标圈舍（展示容量/存栏）→ 调 transfer 接口；
   - 「移出圈舍」：二次确认 → 调 remove-from-pen。
3. 圈舍列表/详情页存栏数刷新（现有接口已返回 current_count，重新拉取即可）。

### 6.3 验收标准

- [ ] 圈舍详情可将畜禽转入其他圈舍，耳标自动重生、两圈舍存栏正确；
- [ ] 可移出圈舍（无圈舍状态），耳标释放，重新入舍可复用；
- [ ] 目标圈舍已满时拦截并提示。

## 七、缺口 6：审核结果通知闭环（P2）

### 7.1 现状

- `app/modules/review/service.py` 统一审核通过/驳回后仅改业务表 `audit_status`，**无任何通知**。
- `sys_notice` 是场主手发公告，与审核无关。
- 员工被驳回后只能自己翻列表看状态，体验断链；功能描述模块名为"审核通知模块"。

### 7.2 方案

**后端（数据库）**：新建 `sys_message` 站内信表：
```
farm_id, receiver_user_id, message_type(审核结果/系统提醒), title, content,
related_module(如 feeding/inventory/health), related_id, is_read(0/1), create_time
```

**后端（接口与钩子）**：
1. 审核钩子：在 `review/service.py` 统一审核入口（或各模块 `audit_xxx`）审核完成后，若提交人存在（`operator_user_id / consumer_user_id`，需确认各业务表提交人字段，缺的补齐），向提交人插入一条 `审核结果` 消息（通过/驳回 + 备注）；
2. 新增接口（挂在 system 模块，超管/场主/员工均可查自己的）：
   - `GET /system/messages`（分页、按 is_read 筛选，仅本人消息）；
   - `GET /system/messages/unread-count`（未读数，供顶栏角标）；
   - `PUT /system/messages/{id}/read` 与 `PUT /system/messages/read-all`。

**前端**：
1. `HeaderBar.vue`：增加「消息铃铛」图标 + 未读红点角标（登录后拉 unread-count，审核操作后刷新）；
2. 新增 `views/system/MessageListView.vue`（或并入个人中心 `/profile`）：消息列表 + 全部已读 + 点击跳转相关记录页；
3. `review.ts` / `system.ts` 封装对应 API。

### 7.3 验收标准

- [ ] 员工提交 → 场主驳回/通过后，员工消息铃铛出现未读 + 列表可见内容；
- [ ] 已读后角标消失；只读自己的消息（多租户隔离）；
- [ ] 超管/场主审核自己的操作不产生给自己消息（或按角色过滤）。

## 八、缺口 7：移动端浏览器适配（最后实施，本期仅记录）

- 现状：`DefaultLayout.vue` 固定 220px 侧边栏 + 顶栏，无响应式断点，表格溢出，手机浏览器不可用。
