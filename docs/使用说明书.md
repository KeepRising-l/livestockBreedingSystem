## 一、系统概述

### 1.1 系统定位

面向中小型养殖场的全流程管理系统，覆盖 **入栏 → 饲喂 → 防疫诊疗 → 繁育 → 审核 → 库存 → 出栏** 的完整养殖生产链路。

一句话概括：**谁养了什么、养在哪、喂了什么、生了没、卖了多少钱，一个网页里全都查得到。**

### 1.2 支持的畜种

系统内置 **牛（cattle）、羊（sheep）、猪（pig）** 三个畜种，各自拥有独立的圈舍、档案、饲喂、繁育与统计口径。

一个养殖场可以同时经营多个畜种，畜种之间数据互不干扰（详见 [4.4 多畜种切换](#44-多畜种切换)）。

### 1.3 四个核心概念

| 概念 | 说明 |
| --- | --- |
| **养殖场（租户）** | 数据的最高隔离单位。不同养殖场之间完全看不到彼此的数据（多租户隔离） |
| **畜种** | 牛/羊/猪。决定生长阶段口径、圈舍分配、妊娠期天数、繁育规则 |
| **圈舍** | 畜禽的物理存放位置，编号如 `A02`。圈舍带类型与畜种属性，决定新入栏畜禽的去向与耳标前缀 |
| **耳标** | 每头畜禽的唯一身份编号，所有业务记录都挂在耳标上。由系统自动生成，无需手工编 |

### 1.4 审核机制（重要）

系统区分「**录入**」与「**生效**」两个环节：

- **员工**提交的记录（饲喂、进货、领用、防疫、诊疗、配种）进入 **待审核** 状态
- **场主**在「审核中心」确认无误后 **通过**，记录才正式生效并影响库存、成本、统计
- 审核结果会以站内消息通知提交人

场主自己录入的记录同样走审核流程，保证数据有据可查。

## 二、安装、启动与部署

### 2.1 环境要求

| 组件 | 版本要求 | 默认端口 |
| --- | --- | --- |
| Python | 3.10 及以上（推荐 3.12） | — |
| Node.js | ≥ 20.19（推荐 22 LTS） | — |
| MySQL | 5.7 / 8.0 | 3306 |
| 前端（Vite） | — | 5173 |
| 后端（FastAPI） | — | 8000 |

> Redis 无需安装。后端配置中保留了 Redis 字段，但代码未实际使用。

### 2.2 全新机器环境准备

> 机器上已有 Python / Node / MySQL 可跳过本节，直接看 2.3。

**2.2.1 安装 Python（后端运行环境）**

1. 下载：<https://www.python.org/downloads/>，选 **Python 3.12.x**（3.10 及以上均可）
2. 安装时 **务必勾选 `Add python.exe to PATH`**（安装界面底部的复选框）
3. 验证（新开一个终端）：

```powershell
python --version   # 应输出 Python 3.12.x
pip --version
```

> 国内下载慢可用镜像：<https://mirrors.huaweicloud.com/python/>

**2.2.2 安装 Node.js（前端运行环境）**

1. 下载：<https://nodejs.org/>，选 **Node.js 22 LTS**（Vite 8 要求 Node ≥ 20.19）
2. 一路默认安装即可（自带 npm）
3. 验证：

```powershell
node --version   # 应输出 v22.x
npm --version
```

可选：配置国内镜像加速依赖安装

```powershell
npm config set registry https://registry.npmmirror.com
```

**2.2.3 安装 MySQL**

1. 下载：<https://dev.mysql.com/downloads/installer/>，选 **MySQL Community Installer**（含 Server + Workbench）
2. 安装要点：
   - 配置类型选 `Server only` 或 `Custom`
   - 认证方式保持默认 `Use Strong Password Encryption`
   - **设置并牢记 root 密码**（后面 `.env` 要用）
   - Windows 服务保持默认勾选，开机自启
3. 验证服务已启动：

```powershell
mysql -u root -p        # 输入密码后进入 mysql> 提示符
```

**2.2.4 获取项目代码**

把整个项目目录复制到目标机器（U 盘 / Git 仓库 / 压缩包均可），例如 `D:\Code\system`，需包含 `livestock-web` 与 `livestock_server` 两个子目录。

> **不要**复制旧机器的 `livestock_server/venv/`、`livestock-web/node_modules/`、`livestock-web/dist/` —— 这些需在新环境重建。

### 2.3 数据库初始化

用 root 登录 MySQL 后执行：

```sql
CREATE DATABASE IF NOT EXISTS livestock_db
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

-- 可选：为项目单独建一个账号，避免使用 root
CREATE USER IF NOT EXISTS 'livestock'@'%' IDENTIFIED BY 'livestock_123456';
GRANT ALL PRIVILEGES ON livestock_db.* TO 'livestock'@'%';
FLUSH PRIVILEGES;
```

> 使用独立账号时，把该账号密码填到 `.env` 的 `DB_USER` / `DB_PASSWORD`。

**数据表无需手工创建**。后端首次启动会自动完成：

1. `Base.metadata.create_all()` 创建全部数据表（与代码模型始终一致）
2. 创建超级管理员账号（默认 `admin / admin123`，可用 `.env` 覆盖）
3. 初始化字典数据与 RBAC 角色、菜单

老库升级所需的轻量迁移（补列、回填存量数据）也已内置在启动流程中。

### 2.4 后端部署与启动

**2.4.1 配置环境变量**

```powershell
cd D:\Code\system\livestock_server
Copy-Item .env.example .env
notepad .env
```

必须修改的项（其余可保持默认）：

```ini
# 数据库：填本机 MySQL 的账号密码
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root                    # 或 2.3 里建的 livestock
DB_PASSWORD=你的MySQL密码        # 务必修改
DB_NAME=livestock_db

# JWT 密钥：改成任意随机字符串（≥32 位）
JWT_SECRET_KEY=改成你自己的随机字符串至少32位长度

# 超级管理员初始账号（仅当 admin 不存在时创建）
SUPER_ADMIN_USERNAME=admin
SUPER_ADMIN_PASSWORD=admin123
```

> `DB_ECHO`（默认 `false`）控制是否把每条 SQL 打印到控制台。调试时可临时改为 `true`；平时建议保持关闭，全量打印会刷屏并拖慢终端输出。

**2.4.2 创建虚拟环境并安装依赖**

```powershell
cd D:\Code\system\livestock_server

python -m venv venv
.\venv\Scripts\Activate.ps1        # 每次新开终端都要执行
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

> PowerShell 报错「在此系统上禁止运行脚本」时，执行一次
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`，输入 Y 确认后重新激活。

**2.4.3 启动后端**

```powershell
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

启动成功标志：

```
[启动] 智能养殖信息管理系统 初始化中...
[启动] 智能养殖信息管理系统 已就绪，访问 http://127.0.0.1:8000/docs 查看接口文档
INFO:     Uvicorn running on http://0.0.0.0:8000
```

验证：

- <http://127.0.0.1:8000/health> 返回 `{"status":"up"}`
- <http://127.0.0.1:8000/docs> 能看到 Swagger 接口文档

> 开发期可加 `--reload` 实现代码热重载；演示 / 生产环境不要加。

**2.4.4 导入演示数据（可选，建议）**

以下脚本通过 TestClient 调真实 API 造数，**无需先启动后端服务**。均在 `livestock_server` 目录、虚拟环境激活状态下执行：

```powershell
python init_sunshine_data.py     # 阳光牧场（牛/羊/猪 全套数据，会清空重建数据库）
python init_bajie_data.py        # 八戒牧场（仅猪；需先设 $env:BAJIE_PASSWORD='xxx'）
python seed_missing_tables.py    # 补齐空表（公畜档案/公告/站内消息/档案历史），可重复执行
python seed_data.py              # 重建畜禽档案测试数据（会清空 animal 表）
```

推荐执行顺序：① → ② → ③（→ ④ 可选）。每步执行完都有打印提示。

### 2.5 前端部署与启动

```powershell
cd D:\Code\system\livestock-web
npm install
npm run dev
```

启动成功后终端显示：

```
VITE v8.x  ready in xxx ms
➜  Local:   http://localhost:5173/
```

浏览器打开 <http://localhost:5173> 即可。

**前端接口地址配置**（`livestock-web/.env.development`）：

```ini
VITE_API_BASE=/api/v1
```

该相对路径会走 **Vite 开发代理**（`vite.config.ts` 的 `server.proxy` 把 `/api` 转发到 `http://127.0.0.1:8000`），请求同源、不触发跨域预检。后端 CORS 另已放行本机任意端口，因此 5173 被占用、Vite 自动改用 5174 时也能正常访问。

> 若后端不在本机 8000 端口，改 `vite.config.ts` 的 `server.proxy.target` 即可。修改前端配置后需要重启 dev server。

### 2.6 日常启动顺序

每次开机后只需启动两个服务（MySQL 是 Windows 服务，已随系统自启）：

```powershell
# 终端 1：后端
cd D:\Code\system\livestock_server
.\venv\Scripts\Activate.ps1
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# 终端 2：前端
cd D:\Code\system\livestock-web
npm run dev
```

启动检查清单：

- [ ] `http://127.0.0.1:8000/health` 返回 `{"status":"up"}`
- [ ] `http://localhost:5173` 能打开登录页
- [ ] `admin / admin123` 登录成功，进入数据大屏
- [ ] 侧边栏「我的养殖场」可展开且各页面数据正常

### 2.7 生产构建与部署（可选）

**前端打包**

```powershell
cd D:\Code\system\livestock-web
npm run build          # 产物输出到 livestock-web/dist
```

生产环境 `.env.production` 的 `VITE_API_BASE=/api/v1` 为相对路径，因此需要 Nginx 把 `dist` 静态资源与 `/api/` 一起反代到后端 8000 端口：

```nginx
server {
    listen 80;
    root  D:/Code/system/livestock-web/dist;
    index index.html;
    location / { try_files $uri $uri/ /index.html; }
    location /api/ { proxy_pass http://127.0.0.1:8000; }
}
```

**后端生产启动**（去掉 `--reload`，建议用 nssm / 任务计划做服务守护）：

```powershell
.\venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 2.8 部署故障排查

| 现象 | 原因 / 解决 |
| --- | --- |
| `Activate.ps1 禁止运行脚本` | 执行 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| `pip install` 超时 / 失败 | 换镜像 `-i https://pypi.tuna.tsinghua.edu.cn/simple`；确认 Python ≥ 3.10 |
| 后端报 `Can't connect to MySQL` | MySQL 服务未启动（`net start mysql` 或检查服务面板）；或 `.env` 的 `DB_PASSWORD` 错误；或 `livestock_db` 未创建（见 2.3） |
| 后端报 `Unknown database` | 未执行 2.3 的建库 SQL |
| 前端页面空白、接口全红 | 后端没启动；或前端配置的后端地址 / 端口不对 |
| 端口 5173 被占用 | Vite 会自动切到 5174 等端口，无需处理（CORS 已支持本机任意端口） |
| 端口 8000 被占用 | `netstat -ano \| findstr :8000` 找到占用进程结束，或改 `.env` 的 `APP_PORT` 并同步调整 `vite.config.ts` 的 proxy target |
| 浏览器报 CORS / 跨域错误 | 确认前端是通过 `localhost`（本机）访问；后端 CORS 正则应放行本机端口 |
| 忘记 admin 密码 | 删除 `sys_user` 表中 admin 行，改 `.env` 的 `SUPER_ADMIN_PASSWORD` 后重启后端即可重建 |
| 需要从另一台机器的浏览器访问 | 把 `vite.config.ts` 的 proxy target 改为后端机器的局域网 IP（或在 `.env.development` 用绝对地址 `http://后端IP:8000/api/v1`），并在防火墙放行 8000 / 5173 |
| 演示数据脚本报登录失败 | 确认执行顺序（先阳光牧场、后八戒牧场）；`init_bajie_data.py` 需先设 `$env:BAJIE_PASSWORD` |

## 三、账号、角色与权限

### 3.1 登录

打开首页 → 输入账号与密码 → 点击「登 录」。

登录成功后，系统根据角色自动跳转到不同落地页：

| 角色 | 登录后落地页 |
| --- | --- |
| 超级管理员 / 养殖场主 | 数据大屏 |
| 员工 | 我的工作台 |

### 3.2 三种角色

| 角色 | userType | 权限范围 | 典型账号 |
| --- | --- | --- | --- |
| **超级管理员** | 1 | 系统维护 + 可切换查看任意养殖场。拥有全部业务模块权限 | `admin / admin123` |
| **养殖场主** | 2 | 本养殖场全部业务模块（不含系统管理）+ 审核 + 员工与薪资管理 | `sunshine / 123456` |
| **员工** | 3 | 按岗位分配，只能看到自己岗位相关的菜单与操作 | `feeder01 / 123456` |

### 3.3 员工岗位与工作台

员工按「岗位」自动关联默认角色，登录后进入 **我的工作台**，只显示本职工作的待办：

| 岗位 | 工作台内容 |
| --- | --- |
| 饲喂员 | 今日待喂圈舍、饲喂记录登记、饲喂方案查看 |
| 兽医 | 防疫记录、诊疗记录登记 |
| 繁育员 | 配种记录、繁育预警（孕检/临产/未发情提醒） |
| 库管员 | 库存不足提醒、领用登记、进货登记 |

> 员工账号由场主在「养殖场管理 → 员工管理」中创建，系统**不开放员工自助注册**。

### 3.4 养殖场主注册

访问首页的注册入口，填写养殖场信息（含养殖场名称、可选畜种等）即可注册场主账号。

> 注册时选择的「养殖种类」决定后续侧边栏出现几个畜种目录。注册时只选了牛，之后就不会出现羊场、猪场。

### 3.5 个人中心与密码

- **个人中心**：右上角头像 → 个人中心，查看本人的账号信息、角色与权限模块
- **忘记密码**：联系超级管理员，在「系统管理 → 用户管理」中重置，或由场主在员工管理中重置
- **登录日志**：系统记录每次登录的账号、时间、IP、浏览器，可在「系统管理 → 日志管理」查询

- **内容区**：当前功能页面

### 4.2 侧边栏菜单结构

菜单按角色动态生成，顶层结构如下：

| 顶层菜单 | 可见角色 | 内容 |

| **系统管理** | 仅超管 | 用户管理、角色管理、日志管理、通知公告 |

「我的养殖场」下按畜种展开，每个畜种包含 9 个业务模块：

| 模块 | 包含页面 |
| --- | --- |
| 圈舍管理 | 圈舍列表 |
| 档案管理 | 畜禽档案、个体入栏、批量入栏、历史记录 |
| 饲喂管理 | 饲喂方案、饲喂记录 |
| 物资库存 | 物资库存、进货记录、领用记录 |
| 防疫诊疗 | 防疫记录、诊疗记录 |
| 繁育管理 | 母畜档案、公畜档案、配种记录、产犊记录、繁育预警 |
| 审核中心 | 待审核列表 |
| 销售财务 | 销售订单、成本支出、利润核算、薪资记录 |
| 统计分析 | 综合统计、存栏繁育统计、防疫诊疗统计、物资消耗统计、财务统计 |

### 4.3 顶部栏功能

| 控件 | 作用 |
| --- | --- |
| 折叠按钮 | 收起/展开侧边栏（收起后只剩图标，鼠标悬停显示浮层菜单） |
| 消息通知 | 显示未读站内消息数；点击进入「我的消息」查看审核结果通知 |
| 农场切换 | **仅超管可见**（只要有农场就展示），显示并切换当前操作的养殖场 |
| 头像 | 个人中心、退出登录 |

### 4.4 多畜种切换

「我的养殖场」下会按该场注册的畜种列出「牛场 / 羊场 / 猪场」：

- 点击某个畜种，即切换到该畜种的数据视图，各畜种数据互不干扰
- 菜单为**手风琴模式**（同时只展开一个），打开新目录会自动收起上一个
- 养殖场注册时选了哪几种畜，这里就出现几个目录

> 示例：阳光牧场注册了牛、羊、猪三个畜种，因此侧边栏会出现三个畜种目录；八戒牧场只注册了猪，就只有一个「猪场」。

## 五、功能模块详解

### 5.1 数据大屏

登录后的默认首页（员工除外），用于一眼掌握全场状况。

**展示内容**

- 核心 KPI：今日存栏、本月入栏 / 出栏、累计销售额、累计利润
- 图表：圈舍分布、畜种分布、生长阶段分布、入栏出栏趋势
- 待办提醒：待审核记录数、待处理繁育预警数

**导出报表**

点击右上角「导出 Excel」，一键下载全场报表文件（含 KPI、今日待办、入栏出栏趋势、畜种分布、生长阶段、圈舍存栏等多个工作表）。

> 导出功能按需加载 Excel 处理库：点击导出时才会下载相关代码，不影响页面打开速度。

### 5.2 圈舍管理

**圈舍列表**：查看本场全部圈舍及其类型、容量、当前存栏数。

**新增 / 编辑圈舍**，需填写：

| 字段 | 说明 |
| --- | --- |
| 圈舍编号 | 如 `A02`。编号中的数字部分会参与耳标生成，请按规则编排 |
| 圈舍类型 | A / B / C / D（见下表） |
| 容量 | 该圈舍可容纳的最大畜禽数，入栏时校验 |
| 畜种 | 该圈舍饲养的畜种。**未指定畜种的圈舍无法入栏**（耳标前缀需要它） |

**圈舍类型对照**

| 代码 | 名称 | 用途 |
| --- | --- | --- |
| A | 育雏舍 | 幼龄畜禽 |
| B | 育成舍 | 生长发育期 |
| C | 繁育舍 | 配种、妊娠、产犊 |
| D | 种畜圈舍 | 种用公畜 / 母畜 |

**圈舍详情**：点击圈舍可查看该圈舍内的畜禽列表。

### 5.3 档案管理

畜禽档案是整个系统的数据主线，所有业务记录都关联耳标。

#### 5.3.1 畜禽档案（列表）

- 按耳标、畜种、圈舍、生长阶段、状态等条件筛选
- 每条档案展示：耳标、品种、性别、出生日期、日龄、生长阶段、所在圈舍、当前状态
- 点击可进入「档案详情」，查看完整信息与该畜禽的历史记录

#### 5.3.2 个体入栏

适用于单头畜禽入栏：

1. 选择圈舍（下拉只显示有剩余容量、且已指定畜种的圈舍）
2. 填写品种、性别、出生日期、入栏日期、来源、备注等
3. 提交后系统 **自动生成耳标** 并分配圈舍

#### 5.3.3 批量入栏

适用于一次性入库多只，提供两种方式：

**方式一：手工逐行添加** —— 在页面上逐行填写，适合少量。

**方式二：从 Excel 导入**（推荐）

1. 点击右上角「从 Excel 导入」→「下载模板」
2. 按模板填写每头畜禽的：品种、性别、出生日期（必填）、入栏日期、来源、备注
3. 上传文件 → 系统解析并 **预览** 结果
4. 确认后导入

导入过程的容错说明：

- 表头支持模糊匹配（如模板列名「出生日期（必填）」也能识别为「出生日期」）
- 有问题的行会被 **跳过并在结果中标明失败原因**，不影响其它行正常导入

#### 5.3.4 历史记录

记录畜禽的关键变更（转圈舍、状态变更等），支持查看与恢复。

### 5.4 饲喂管理

#### 饲喂方案

维护本场的饲喂方案（按畜种 / 生长阶段区分），方案包含饲料配比与 **单位成本自动计算**。

#### 饲喂记录

记录每日实际饲喂情况：

1. 选择圈舍
2. 选择使用的饲喂方案
3. 填写饲喂数量、时间等

系统会校验 **同一天、同一时段、同一圈舍不可重复登记**，避免重复记账。

提交后进入待审核状态，场主审核通过后才计入成本统计。

### 5.5 物资库存

#### 物资库存

查看物资的当前库存量与状态。物资类型限定为 **饲料 / 疫苗 / 兽药** 三类。

系统自动维护两项指标：

| 指标 | 取值 | 判定规则 |
| --- | --- | --- |
| 库存状态 | 正常 / 即将过期 / 已过期 | 有效期早于今天 → 已过期；有效期距今 ≤ 30 天 → 即将过期 |
| 缺货标记 | 是 / 否 | 库存数量低于该物资设定的预警阈值 |

#### 进货记录

登记采购入库：物资名称、数量、单价、供应商、进货日期等。

场主审核 **通过后自动同步库存**：按「物资类型 + 名称」匹配已有库存，存在则增加数量、不存在则自动建档，并按 **移动加权平均** 重算库存均价：

```
新均价 = (原库存量 × 原均价 + 本次进货量 × 本次单价) ÷ 新库存总量
```

审核未通过则完全不影响库存。**已审核通过的记录不允许删除。**

#### 领用记录

登记物资领用出库。审核通过后 **自动扣减库存**，并记录领用当时的 **单价快照**，避免后续进货改价影响历史成本核算。

> 员工提交时会校验一次库存是否充足，场主审核时再校验一次（防止并发导致的超领）。库存不足的记录无法审核通过。

### 5.6 防疫诊疗

#### 防疫记录

登记疫苗接种，支持 **批量登记**。疫苗类型受字典白名单约束。

#### 诊疗记录

登记患病与治疗情况：症状、诊断、用药、治疗结果等。

两类记录提交后均需场主审核。

### 5.7 繁育管理

#### 母畜档案 / 公畜档案

维护可参与繁育的种畜信息。母畜拥有 **生理状态**（正常 / 发情 / 妊娠 / 泌乳 / 休情 / 淘汰），该状态会影响能否配种。

#### 配种记录

1. 选择母畜（系统校验其是否已达可繁育日龄、是否处于可配种状态）
2. 填写配种日期、配种方式、公畜等
3. 提交后系统 **自动计算预产期**（配种日期 + 该畜种妊娠期天数）

> 已处于「妊娠」状态的母畜不可重复配种；已登记孕检的记录不允许修改配种日期。
>
> 配种记录同样需要场主在「审核中心」审核通过后，才正式生效并计入繁育统计。

#### 产犊记录

登记产仔结果，系统 **自动计算存活率**。

#### 繁育预警

系统按规则自动生成待处理提醒：

| 预警类型 | 触发规则 |
| --- | --- |
| 孕检提醒 | 配种后满 60 天仍未登记孕检 |
| 临产提醒 | 距预产期 15 天以内 |
| 未发情提醒 | 产犊后满 60 天仍无配种记录 |

预警也支持手动处理（标记为已处理）。

### 5.8 审核中心

场主统一处理六类待审核记录：

| 类别 | 说明 |
| --- | --- |
| 饲喂 | 饲喂记录 |
| 进货 | 物资采购入库 |
| 领用 | 物资领用出库 |
| 防疫 | 疫苗接种记录 |
| 诊疗 | 诊疗记录 |
| 配种 | 配种记录（审核通过后才计入繁育统计） |

每条记录可 **通过** 或 **驳回**；驳回时填写原因，结果通过站内消息通知提交人。

### 5.9 销售财务

## 六、典型业务流程

### 6.1 新畜禽入栏

```
建圈舍 → 指定畜种 → 入栏 → 自动生成耳标 → 自动判定生长阶段
```

1. 「圈舍管理」新增圈舍，选择类型、容量、畜种
2. 「档案管理 → 个体入栏」或「批量入栏」录入畜禽
3. 系统自动生成耳标并分配到有空位的圈舍
4. 出生日期用于自动判定生长阶段，日龄随日期自动增长

### 6.2 日常饲喂

```
饲喂员登记 → 场主审核 → 计入成本
```

1. 饲喂员在工作台或「饲喂管理 → 饲喂记录」登记本次饲喂
2. 场主在「审核中心」确认通过
3. 通过后记录正式生效，参与成本与统计

### 6.3 繁育全流程

```
公母畜建档 → 配种（自动算预产期）→ 繁育预警提醒孕检 → 孕检登记
    → 临产提醒 → 产犊记录（自动算存活率）→ 母畜转泌乳状态
```

### 6.4 采购与领用

```
进货登记 → 场主审核 → 库存增加、均价更新
领用登记 → 场主审核 → 库存扣减、成本归集
```

### 6.5 出栏销售

```
销售订单选耳标 → 自动算出栏天数与金额 → 计入利润核算
```

## 七、业务规则速查

> 以下规则均取自后端实现，可作为演示与答辩的讲解依据。

### 7.1 耳标生成规则

耳标共 **5 位**，由三段拼接：

```
[畜种位 1 位] + [圈舍编号数字 2 位] + [入栏序号 2 位]
```

- **畜种位**：牛=1、羊=2、猪=3
- **圈舍编号数字**：取圈舍编号中的数字部分（如 `A02` 取 `02`）
- **入栏序号**：该圈舍内的顺序号，从 `01` 起

**示例**：在 `A02` 号牛舍入栏第 7 头牛 → 耳标为 `10207`

补充规则：

- 序号 **自动复用已释放的号**（档案删除后空出的号会被重新分配），避免号段无谓增长
- 圈舍必须已指定畜种，否则无法生成耳标；圈舍编号中若不含数字同样无法生成

### 7.2 生长阶段判定

按畜种与日龄自动判定，系统每日凌晨自动刷新在栏畜禽的阶段：

| 牛 | 日龄区间 | | 羊 | 日龄区间 | | 猪 | 日龄区间 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 犊牛期 | 1–60 | | 羔羊期 | 1–45 | | 仔猪期 | 1–28 |
| 保育期 | 61–180 | | 保育期 | 46–90 | | 保育期 | 29–70 |
| 生长期 | 181–365 | | 生长期 | 91–180 | | 生长期 | 71–120 |
| 育肥期 | 366–540 | | 育肥期 | 181–270 | | 育肥期 | 121–180 |

> 「妊娠」阶段由配种记录单独标记，优先级高于上述基础阶段。

### 7.3 繁育相关参数

| 参数 | 牛 | 羊 | 猪 |
| --- | --- | --- | --- |
| 妊娠期（预产期 = 配种日 + 此天数） | 280 天 | 150 天 | 114 天 |
| 可繁育起始日龄 | 365 天 | 300 天 | 220 天 |

**繁育预警触发条件**：配种后满 60 天未孕检 / 距预产期 15 天内 / 产犊后满 60 天未配种。

### 7.4 母畜生理状态

`正常` / `发情` / `妊娠` / `泌乳` / `休情` / `淘汰`

其中「妊娠」状态由配种记录自动标记，处于该状态时不允许重复配种。

### 7.5 审核与数据生效

- 需审核的记录类型：**饲喂、进货、领用、防疫、诊疗、配种**（共 6 类）
- 未审核的记录 **不参与** 库存增减与统计口径
- 审核结果通过站内消息通知提交人

### 7.6 库存状态与成本核算

| 规则 | 说明 |
| --- | --- |
| 物资类型白名单 | 仅允许 `饲料` / `疫苗` / `兽药` 三类 |
| 过期预警阈值 | 有效期距今 ≤ 30 天 → 即将过期；已过有效期 → 已过期 |
| 缺货判定 | 库存数量低于该物资设定的预警阈值 |
| 进货改价 | 审核通过时按移动加权平均重算库存均价 |
| 领用成本 | 记录领用当时的单价快照，不受后续改价影响 |
| 并发保护 | 提交时与审核时各校验一次库存充足性，库存不足无法审核通过 |

### 7.7 自动任务

系统每日凌晨自动执行以下维护任务（北京时间）：

| 时间 | 任务 |
| --- | --- |
| 00:05 | 刷新所有在栏畜禽的生长阶段 |
| 00:10 | 扫描并生成繁育预警（孕检 / 临产 / 未发情） |
| 00:20 | 刷新物资库存的过期 / 缺货状态 |
| 00:30 | 清理超过 180 天的历史档案记录 |

## 八、常见问题（FAQ）

**Q1：登录后页面空白、接口报错？**

检查后端是否已启动（访问 http://127.0.0.1:8000/health 应返回 `{"status":"up"}`），以及前端配置的后端地址是否正确。

**Q2：员工登录后看不到很多菜单，是坏了吗？**

正常。员工按岗位只能看到本职相关的菜单，这是权限设计。

**Q3：为什么点「牛场」/「羊场」没有反应或看不到？**

说明该养殖场注册时没有选择对应畜种。只有注册时选中的畜种才会出现在侧边栏。

**Q4：为什么要审核？我提交的记录去哪了？**

员工提交的饲喂、防疫等记录会先进入「待审核」，需场主在审核中心确认通过后才生效。这是为了保证数据准确。

**Q5：入栏时提示无法生成耳标？**

两个常见原因：圈舍未指定畜种；或圈舍编号中不含数字。请先在圈舍管理中补全。

**Q6：入库的物资库存没变化？**

进货/领用记录需要场主审核通过后才会影响库存。

**Q7：如何调整品种下拉里的选项（如增加「娟姗牛」）？**

品种数据存放在后台字典中，业务页面的品种下拉会自动读取它。早期版本可以通过「系统管理 → 字典管理」界面维护，该入口目前已下线，需要由管理员直接在数据库层面调整字典数据。

> 注意：品种仅作为档案上的标签展示。系统的生长阶段、圈舍分配、饲喂与繁育口径均按 **畜种（牛/羊/猪）** 计算，不按品种区分。

**Q8：忘记密码怎么办？**

联系超管在「系统管理 → 用户管理」中重置。

**Q9：多个养殖场的数据会串吗？**

不会。系统按养殖场做数据隔离，场主只能看到本场数据。超管可在顶部栏切换要查看的养殖场。

**Q10：侧边栏菜单很卡，展开不流畅？**

侧边栏菜单数量与该场经营畜种数成正比（每个畜种都有完整的 9 个模块）。同时经营三个畜种时菜单规模最大。系统已针对展开动画做了性能优化；若仍有明显卡顿，可反馈具体的畜种配置与浏览器环境。

### 9.2 术语表

| 术语 | 含义 |
| --- | --- |
| 耳标 | 畜禽的唯一身份编号，5 位，由系统自动生成 |
| 圈舍 | 畜禽的物理存放单元，带编号、类型、容量、畜种属性 |
| 入栏 / 出栏 | 畜禽进场登记 / 销售离场 |
| 生长阶段 | 按日龄自动判定的发育阶段（犊牛期、育肥期等） |
| 妊娠期 | 从配种到分娩的天数，按畜种固定（牛 280 / 羊 150 / 猪 114） |
| 预产期 | 配种日期 + 妊娠期，系统自动计算 |
| 生理状态 | 母畜当前的繁殖状态（正常/发情/妊娠/泌乳/休情/淘汰） |
| 待审核 | 员工提交后、尚未经场主确认的记录状态 |
| 多租户 | 不同养殖场之间数据完全隔离的机制 |

### 9.4 Linux 等价命令速查

Windows 之外的系统（含服务器部署）可用以下等价命令：

```bash
# Python 虚拟环境
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt

# 启动后端
uvicorn app.main:app --host 0.0.0.0 --port 8000

# 创建数据库
mysql -uroot -p -e "CREATE DATABASE livestock_db DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 前端
npm install && npm run dev
```
