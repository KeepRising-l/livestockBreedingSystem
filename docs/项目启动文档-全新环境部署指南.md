# 项目启动文档（全新环境从零部署指南）

> 适用场景：在一台**全新的机器**上（无 Python、无 Node、无任何环境）部署并运行本项目。
> 本文以 **Windows 10/11** 为主线编写，关键步骤附 Linux 等价命令。
> 系统默认目标：前端 `http://localhost:5173`，后端 `http://127.0.0.1:8000`，数据库 `MySQL 8.0`。

---

## 一、项目结构与技术栈

```
system/
├── livestock-web/        # 前端：Vue 3 + Vite + Element Plus + Pinia + ECharts
├── livestock_server/     # 后端：FastAPI + SQLAlchemy 2 + MySQL + APScheduler
├── docs/                 # 文档
└── landing/              # 静态落地页（可选，不影响系统运行）
```

| 组件 | 技术 | 端口 |
| --- | --- | --- |
| 前端 | Vue 3.5 / Vite 8 / Element Plus 2.14 / TypeScript | 5173 |
| 后端 | FastAPI / SQLAlchemy / PyMySQL / JWT | 8000 |
| 数据库 | MySQL 8.0（5.7 亦可），库名 `livestock_db` | 3306 |

> **Redis 无需安装**：后端配置里保留了 Redis 字段，但代码未实际使用。

---

## 二、环境准备（全新机器）

### 2.1 安装 Python（后端运行环境）

1. 下载地址：<https://www.python.org/downloads/>，选择 **Python 3.12.x**（3.10 及以上均可，与本机开发版本一致）。
2. 安装时**务必勾选 `Add python.exe to PATH`**（安装界面底部的复选框）。
3. 验证（新开一个终端）：

```powershell
python --version   # 应输出 Python 3.12.x
pip --version
```

> 国内下载慢可使用镜像站：<https://mirrors.huaweicloud.com/python/> 或淘宝软件中心搜索 Python。

### 2.2 安装 Node.js（前端运行环境）

1. 下载地址：<https://nodejs.org/>，选择 **Node.js 22 LTS**（Vite 8 要求 Node ≥ 20.19，选 22 LTS 最稳）。
2. 一路默认安装即可（会自带 npm）。
3. 验证：

```powershell
node --version   # 应输出 v22.x
npm --version
```

4. （可选）配置国内镜像，加速后续依赖安装：

```powershell
npm config set registry https://registry.npmmirror.com
```

### 2.3 安装 MySQL 8.0

1. 下载地址：<https://dev.mysql.com/downloads/installer/>，选择 **MySQL Community Installer**（含 MySQL Server + Workbench 图形工具）。
2. 安装要点：
   - 配置类型选 `Server only`（只要数据库服务）或 `Custom` 自选；
   - 认证方式保持默认 `Use Strong Password Encryption`；
   - **设置并牢记 root 密码**（后面 `.env` 要用）；
   - Windows 服务保持默认勾选，开机自启动。
3. 安装完成后，用命令行验证服务已启动：

```powershell
mysql -u root -p        # 输入密码后进入 mysql> 提示符
```

### 2.4 获取项目代码

把整个项目目录复制到新机器（U 盘 / Git 仓库 / 压缩包均可），例如放到 `D:\Code\system`。
需要包含两个子目录：`livestock-web` 和 `livestock_server`。

> 注意：**不要**复制旧机器的 `livestock_server/venv/`、`livestock-web/node_modules/`、`livestock-web/dist/` 目录（新环境需要重建，见下文）。

## 三、数据库初始化（含 SQL 脚本）

### 3.1 创建数据库

用 root 登录 MySQL 后，执行以下 SQL（也可以保存为 `docs/init_database.sql` 用 `mysql -u root -p < init_database.sql` 导入）：

```sql
-- ============================================================
-- 智能养殖信息管理系统 数据库初始化脚本
-- 只需创建数据库；所有数据表由后端首次启动时自动创建（见 3.2）
-- ============================================================
CREATE DATABASE IF NOT EXISTS livestock_db
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

-- （可选）为项目单独建一个账号，避免使用 root
CREATE USER IF NOT EXISTS 'livestock'@'%' IDENTIFIED BY 'livestock_123456';
GRANT ALL PRIVILEGES ON livestock_db.* TO 'livestock'@'%';
FLUSH PRIVILEGES;
```

> 使用独立账号时，把上面建的用户密码填到第 4 步 `.env` 的 `DB_USER` / `DB_PASSWORD`。

### 3.2 数据表从哪来？（无需手工执行建表语句）

后端在**首次启动时自动完成**以下初始化（代码见 `livestock_server/app/main.py` 的 `init_db()`）：

1. `Base.metadata.create_all()` 自动创建全部数据表（50+ 张，与代码模型始终一致）；
2. 创建超级管理员账号（默认 `admin / admin123`，可用 `.env` 覆盖）；
3. 初始化字典数据（`sys_dict`）与 RBAC 角色菜单（`sys_role` / `sys_menu`）。

因此**不需要**到处找建表 SQL——表结构以代码为准，启动即建。
老库升级场景的轻量迁移（补列、回填）也已内置在启动流程中。

## 四、后端部署与启动

### 4.1 配置环境变量

```powershell
cd D:\Code\system\livestock_server
Copy-Item .env.example .env
notepad .env
```

**必须修改**的项（其余可保持默认）：

```ini
# 数据库：填你本机 MySQL 的账号密码
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root                    # 或 3.1 里建的 livestock
DB_PASSWORD=你的MySQL密码        # 务必修改
DB_NAME=livestock_db

# JWT 密钥：改成任意随机字符串（≥32 位），前后端多实例需一致
JWT_SECRET_KEY=改成你自己的随机字符串至少32位长度

# 超级管理员初始账号（仅当 admin 不存在时创建）
SUPER_ADMIN_USERNAME=admin
SUPER_ADMIN_PASSWORD=admin123
```

### 4.2 创建虚拟环境并安装依赖

```powershell
cd D:\Code\system\livestock_server

# 创建虚拟环境
python -m venv venv

# 激活虚拟环境（每次新开终端都要执行）
.\venv\Scripts\Activate.ps1
```

> **PowerShell 报错「在此系统上禁止运行脚本」时**，执行一次：
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`，输入 Y 确认后重新激活。

```powershell
# 安装依赖（国内建议加清华镜像）
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 4.3 启动后端

```powershell
# 仍保持虚拟环境激活状态
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

启动成功标志（终端输出）：

```
[启动] 智能养殖信息管理系统 初始化中...
[启动] 智能养殖信息管理系统 已就绪，访问 http://127.0.0.1:8000/docs 查看接口文档
INFO:     Uvicorn running on http://0.0.0.0:8000
```

验证：

- 浏览器打开 <http://127.0.0.1:8000/health>，返回 `{"status":"up"}`；
- 浏览器打开 <http://127.0.0.1:8000/docs>，能看到 Swagger 接口文档。

> 开发期可加 `--reload` 实现代码热重载；生产/演示不要加。

### 4.4 导入演示数据（可选，强烈建议）

以下脚本通过 TestClient 调真实 API 造数，**无需先启动后端服务**。均在 `livestock_server` 目录、虚拟环境激活状态下执行。

```powershell

# ③ 补齐 4 张空表（公畜档案/公告/站内消息/档案历史），已有数据则跳过，可重复执行

# ④（可选）重新生成畜禽档案测试数据，会清空 animal 表后重建
```

## 五、前端部署与启动

```powershell
cd D:\Code\system\livestock-web

# 安装依赖（2.2 已配镜像则很快；未配镜像可加 --registry 参数）
npm install

# 启动开发服务器
npm run dev
```

启动成功后终端显示：

```
VITE v8.x  ready in xxx ms
➜  Local:   http://localhost:5173/
```

浏览器打开 <http://localhost:5173>，使用 `admin / admin123` 登录，看到数据大屏即部署完成。

**前端配置说明**（`livestock-web/.env.development`）：

```ini
VITE_API_BASE=http://127.0.0.1:8000/api/v1   # 浏览器直连后端，跨域由后端 CORS 白名单放行
```

> 后端 CORS 已配置 `allow_origin_regex`（放行本机任意端口），即使 5173 被占用、Vite 自动改用 5174 也能正常访问。

## 六、一键启动顺序（日常使用）

每次开机后只需启动两个服务（数据库是 Windows 服务，已自启）：

```powershell
# 终端 1：后端
cd D:\Code\system\livestock_server
.\venv\Scripts\Activate.ps1
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# 终端 2：前端
cd D:\Code\system\livestock-web
npm run dev
```

验证清单：

- [ ] `http://127.0.0.1:8000/health` 返回 `{"status":"up"}`
- [ ] `http://localhost:5173` 能打开登录页
- [ ] `admin / admin123` 登录成功，进入数据大屏
- [ ] 侧边栏「我的养殖场」可展开且各页面数据正常

## 七、生产构建（可选）

```powershell
# 前端打包（产物在 livestock-web/dist）
cd D:\Code\system\livestock-web
npm run build
```

- 生产环境 `.env.production` 的 `VITE_API_BASE=/api/v1` 为相对路径，需要 Nginx 把 `dist` 静态资源与 `/api/` 反代到后端 8000 端口，示例：

```nginx
server {
    listen 80;
    root  D:/Code/system/livestock-web/dist;
    index index.html;
    location / { try_files $uri $uri/ /index.html; }
    location /api/ { proxy_pass http://127.0.0.1:8000; }
}
```

- 后端生产启动（去掉 `--reload`，建议用 nssm / 任务计划做服务守护）：

```powershell
.\venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 八、常见问题排查

| 现象 | 原因 / 解决 |
| --- | --- |
| `Activate.ps1 禁止运行脚本` | 执行 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| `pip install` 超时/失败 | 换镜像 `-i https://pypi.tuna.tsinghua.edu.cn/simple`；确认 Python ≥ 3.10 |
| 后端启动报 `Can't connect to MySQL` | MySQL 服务未启动（`net start mysql` 或检查服务面板）；或 `.env` 的 `DB_PASSWORD` 错误；或 `livestock_db` 库未创建（见 3.1） |
| 后端启动报 `Unknown database` | 未执行 3.1 的建库 SQL |
| 前端页面空白、接口全红 | 后端没启动或 `.env.development` 的 `VITE_API_BASE` 端口不对 |
| 端口 5173 被占用 | Vite 会自动换 5174 等端口，无需处理（CORS 已支持任意本机端口） |
| 端口 8000 被占用 | `netstat -ano \| findstr :8000` 找到占用进程结束，或改 `.env` 的 `APP_PORT` 并同步改前端 `VITE_API_BASE` |
| 浏览器报 CORS 400 / 跨域错误 | 确认前端是通过 `localhost` 访问（非局域网 IP）；后端 `main.py` 的 CORS 正则应放行本机端口 |
| 忘记 admin 密码 | 数据库 `sys_user` 表删除 admin 行，改 `.env` 的 `SUPER_ADMIN_PASSWORD` 后重启后端即可重建 |
| **从另一台机器的浏览器访问前端** | 把 `livestock-web/.env.development` 的 `VITE_API_BASE` 改成 `http://后端机器局域网IP:8000/api/v1`，重启前端，并在后端机器防火墙放行 8000、5173 端口 |
| 演示数据脚本报登录失败 | 确认执行顺序（先 ①再 ②）；`init_bajie_data.py` 需要先 `$env:BAJIE_PASSWORD='xxx'` |
