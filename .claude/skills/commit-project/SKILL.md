# 提交项目代码 + 更新进度文档

每完成一段代码开发（一个模块或一个功能点、验证通过后）执行一次，把本次成果固化到 git 并同步进度文档。

## 第一步：识别本次改动

1. 运行 `git status` 和 `git diff --stat`，列出本次所有改动/新增文件。
2. 按文件路径判断归属模块：
   - `livestock_server/app/modules/<模块>/` → 后端模块
   - `livestock-web/src/views/<模块>/`、`src/api/<模块>.ts` → 前端模块
   - `docs/` → 文档
3. 归纳成一句人话：本次做了什么（哪个模块、新增/修复了什么功能）。

## 第二步：更新进度文档 docs/项目现状分析与实现步骤.md

先 Read 文档头部确认当前版本号，再逐项更新：

1. **版本行**（第 4 行 `> 版本：vX.Y（更新于 ...）`）：
   - 版本号 +0.1（如 v1.6 → v1.7），日期改成当天，末尾追加本次完成事项的简要说明。
2. **功能清单表**（章节一：后端模块表、前端模块表）：
   - 本次新增的功能点在对应模块加行，状态标 `✅ 已实现`；
   - 被修改/重构的行如果状态或描述有变，同步更新。
3. **待办清单 / 剩余模块**（章节二）：
   - 本次完成的项从待办移到已完成（或勾选 ✅）；
   - 剩余模块数、预计剩余天数的统计数字同步扣减。
4. **统计数字**：如页面总数、模块数、接口数等，凡有变化的都改。
5. 更新完后通读一遍改动章节，确保与其他章节一致。

> 若本次改动既有代码又有文档，版本号只 +0.1 一次，不要重复递增。

## 第三步：git 提交

1. `git status` 复查，确认没有误加 `.env`、`venv`、`node_modules`、`dist` 等（已在 .gitignore，正常不会出现）。
2. 按归属分多条提交（同一模块代码 + 对应文档可以合一条），message 遵循仓库风格：
   - 新增功能：`feat(模块): 一句话描述`
   - 文档：`docs: 更新项目进度文档至 vX.Y（...）`
   - 修复：`fix(模块): 一句话描述`
   - 参考最近记录：`git log --oneline -5`
3. 用 `git add` 精确添加本次涉及的文件（不要 `git add -A`），然后 `git commit`（message 用 HEREDOC 支持多行）。

## 第四步：推送

1. `git push origin main`
2. 确认推送成功（无错误输出）。

## 收尾

向用户汇报：本次提交了什么（commit hash + message）、进度文档更新到几版。保持简短。
