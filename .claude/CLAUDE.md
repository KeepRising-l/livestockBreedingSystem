# 项目指令

## 代码完成后的收尾流程

当用户说「提交代码 / 推送代码 / 更新进度文档 / 收尾 / 把这次的代码提交了 / 提交本次开发」等意思时，
自动执行以下收尾流程（等价于 `commit-project` skill，详见 `.claude/skills/commit-project/SKILL.md`）：

1. **识别改动**：`git status` + `git diff --stat`，按文件路径判断改动归属哪些模块。
2. **更新进度文档** `docs/项目现状分析与实现步骤.md`：
   - 版本号 vX.Y +0.1（如 v1.6 → v1.7），日期改当天，末尾追加本次完成事项；
   - 新增功能在模块表格加行标 `✅ 已实现`，状态有变的行同步更新；
   - 待办清单勾选完成项，剩余模块数/预计天数等统计数字扣减；
   - 更新后通读一遍改动章节，保证全文一致。
3. **git 提交**：精确 `git add` 本次文件（不用 `git add -A`），按仓库风格 commit：
   - `feat(模块): 一句话描述` / `docs: 更新项目进度文档至 vX.Y（...）` / `fix(模块): ...`
4. **git push origin main** 推送，确认无错误。
5. 简短汇报：commit hash + message、进度文档更新到几版。

> 此流程与 read-only skill 冲突时，用户明确要求提交代码即为"用户明确要求写入"，可正常执行。
